# 路線的圓滑只做在畫面上，模擬仍走方格

為了劍與魔法的世界觀，車道要看起來是 S 型的彎路，而不是直角折線。我們選擇只在 `src/render/` 讓敵人的移動軌跡、路線線條與射擊線在轉角走弧線。core 仍讓敵人沿著格心之間的直線前進（`src/core/game.ts` 的 `enemyPosition`），射程、瞄準最前面、路障與困住判定都照方格計算。所以畫面上敵人的位置會和模擬位置有落差，只出現在轉角處，不超過半格，弧線也不會離開車道格。這是刻意的：把圓滑移進 core 會牽動路徑、射程與困住規則，平衡也要全部重驗，換來的只是轉角處的精確。

## Considered Options

- **敵人可以斜走（八方向路徑）**：轉角會變成 45°，但 core 的路徑、路障連通性與困住判定都要改，而且仍然不是弧線。
- **脫離方格、改成自由曲線車道**：等於重做核心規則，路障「逼敵人繞路」的玩法也要重新設計。

## Consequences

射擊線要對準畫面上的敵人位置，不能用 core 的格點位置，否則轉角處的射擊線會打在空地上。

**Falsified if:** 玩家能明顯看出塔打不到「畫面上看起來在射程內」的敵人，或塔打中「畫面上看起來在射程外」的敵人；也就是 `src/render/enemies.ts` 畫出的位置和 `src/core/game.ts` 計算射程用的位置差到改變了玩家的判斷。

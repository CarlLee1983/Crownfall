# 場景像素化、資訊覆蓋層全解析度，模型掛在隱形代理之下

為了[美術方向](../art/art-direction.md)要的像素化暗色奇幻畫風，世界先以 2 CSS px 為一像素的低解析度渲染（見 [#103](https://github.com/CarlLee1983/Crownfall/issues/103)），再用最近鄰放大；路線線、射程圈、放置預覽與血條則在放大後，以全解析度、不受霧與遮擋影響地疊在最上層。射擊線、命中閃光、死亡碎片屬於世界，跟著像素化。哪個物件屬於覆蓋層，由建立它的 render 模組明確指定圖層，不靠材質型別推斷。

塔與敵人的 KayKit 模型不取代現有幾何體：原本的方塊、切角柱與圓柱留下來當**代理**，只是不寫入顏色與深度。代理繼續承載坡道上的傾斜與巫妖在坡面上的剪切等變換，模型掛在代理之下並繼承這些變換。這讓 `src/render/enemies.ts` 的支撐行為、[ADR 0002](0002-render-only-path-smoothing.md) 的弧線位置與它們的測試都不必改。

## Considered Options

- **整個畫面像素化，覆蓋物也一起**（原型變體 A）：最接近參考影片，但射程圈與路線線變成鋸齒，敵人融進地面，塔防要的「一眼讀出射程與路線」做不到。
- **不像素化、只換暖色調**（原型變體 C）：最好讀，但失去參考影片的氛圍。
- **用模型直接取代幾何體**：少一層物件，但支撐與剪切要改以模型為基準，坡道與轉彎的既有測試要跟著改。

## Consequences

代理的剪切與傾斜會連帶套用到模型上，坡道上的巫妖會有輕微斜切變形；像素化後不明顯，所以接受。使用載入模型的塔在預載時依縮放後的模型包圍盒取得 picking 高度與半寬。半寬為水平兩軸中較大尺寸的一半，升級後的 picking 高度也包含塔頂標記。因此模型必須在開局前載入完畢。

**Falsified if:** 有一個玩家需要讀取的資訊被放進像素化的世界層而讀不清，或代理的變換讓模型在畫面上明顯穿地、浮空或變形——也就是 `src/render/enemies.ts` 與 `src/render/build-layer.ts` 的代理尺寸和模型外觀對不上到玩家看得出來。
